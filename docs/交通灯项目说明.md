# 交通信号灯控制器 —— 用 MCP 自动生成的完整项目

> 全部梯形图由 MCP 自动生成，经博途导入 + 编译 **0 错误 0 警告**，
> 并用扫描级仿真验证了行为。人工只需在博途里下载运行。

## 一、工程结构

| 块 | 类型 | 说明 |
|---|---|---|
| `FB_交通灯` | FB1 (LAD) | 全部控制逻辑，19 个程序段 |
| `交通灯DB` | IDB (DB2) | `FB_交通灯` 的背景数据块（承载 3 个定时器实例） |
| `Main` | OB1 (LAD) | 只做一件事：调用 `FB_交通灯`，把变量接到引脚上 |

**为什么把逻辑放进 FB 而不是 OB1？**

干净工程里没法用 Openness 建定时器的实例 DB（系统 FB 名不可得），
所以用 **FB 静态变量声明 `IEC_TIMER`** 走"多重实例"路线 —— 不需要任何外部实例 DB。

## 三、控制逻辑

### 正常模式：4 相位循环（26 秒）

| 相位 | 南北 | 东西 | 时长 |
|---|---|---|---|
| 0 | 红灯 | 绿灯 | 10 s |
| 1 | 红灯 | **黄灯闪烁** | 3 s |
| 2 | 绿灯 | 红灯 | 10 s |
| 3 | **黄灯闪烁** | 红灯 | 3 s |
| → | 回到相位 0 | | |

**与题目的对应关系**（题目列表是**先写南北的三个状态、再写东西的三个状态**）：

| 题目原文 | 落在哪个相位 |
|---|---|
| 南北红灯亮 10s | 相位 0（东西同时绿灯 10s）|
| 南北绿灯亮 10s | 相位 2 |
| 南北黄灯闪烁 3s | 相位 3 |
| 东西绿灯亮 10s | 相位 0 |
| 东西黄灯闪烁 3s | 相位 1 |
| 东西红灯亮 10s | 相位 2 + 3 |

> 这样南北红灯实际持续 13s（相位0+1），而不是 10s。
> 这是**标准交通灯**的做法：黄灯期间对向保持红灯，避免"黄灯陷阱"。
> 若要求严格 10s 红灯，需要让南北绿灯与东西黄灯重叠 3s（有安全风险），
> 改法见第六节。

### 紧急模式（越过正常循环，直接点灯）

| 模式 | 南北 | 东西 | 倒计时显示 |
|---|---|---|---|
| 1 | 绿灯 | 红灯 | 99 |
| 2 | 红灯 | 绿灯 | 99 |
| 3 | 红灯 | 红灯 | 99 |
| 4 | 黄灯 | 黄灯 | 99 |

### 内部实现（Static 变量）

| 名称 | 类型 | 作用 |
|---|---|---|
| 秒脉冲定时器 | IEC_TIMER | 产生 1 秒脉冲 |
| 闪灯定时器A / B | IEC_TIMER | 级联产生 1s 亮/1s 灭方波 |
| 秒脉冲 | Bool | 每个扫描周期宽度的秒脉冲 |
| 闪烁位 | Bool | 黄灯闪烁的方波 |
| 阶段 | Int | 当前相位 0~3 |
| 倒计时 | Int | 当前相位剩余秒数 |
| 运行中 | Bool | 启停自保持 |

## 四、19 个程序段

| 段 | 作用 |
|---|---|
| 01 | 停止时初始化：阶段 = 0 |
| 02 | 停止时初始化：倒计时 = 10 |
| 03 | 启动/停止自保持 → 运行中 |
| 04 | 秒脉冲发生器（自复位 TON） |
| 05 | 闪灯 A（1s） |
| 06 | 闪灯 B（1s）→ 方波 |
| 07 | 正常模式：倒计时递减 |
| 08 | 倒计时到 0 → 阶段 + 1 |
| 09 | 阶段 > 3 → 归 0 |
| 10 | 阶段 0 或 2 → 装载 10 秒 |
| 11 | 阶段 1 或 3 → 装载 3 秒 |
| 12 | 倒计时显示：正常模式显示实际值 |
| 13 | 倒计时显示：紧急模式显示 99 |
| 14 | 南北红灯 |
| 15 | 南北绿灯 |
| 16 | 南北黄灯（闪烁） |
| 17 | 东西红灯 |
| 18 | 东西绿灯 |
| 19 | 东西黄灯（闪烁） |

> **注意段 01/02 必须在段 03 之前**：否则冷启动时"运行中"先被置 1，
> 初始化段就永远不执行，状态机会从错误初值起步。

## 六、改法示例

**想改相位时长** → 改段 10/11 里的 MOVE 常量（10 和 3），以及段 02 的初值。

**想让红灯严格 10s** → 把段 15（南北绿灯）加上"东西黄灯相位"条件，
让南北绿灯与东西黄灯重叠，即相位 1 变成"南北绿 + 东西黄闪"。

**想改闪烁频率** → 改段 05/06 的 `T#1s`。

**想加相位** → 改段 09 的回绕阈值，改段 10/11 的装载条件，在灯逻辑里加分支。

## 七、重新生成整个项目

```powershell
$py = 'C:\Users\yourname\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe'
$env:PYTHONIOENCODING = 'utf-8'
$eng = 'C:\PLCMCP\engine\bin\Debug\TiaEngine.exe'

# 1) 建变量表
& $eng --mode ensure_tags --tags '启动按钮@%I0.0,停止按钮@%I0.1,模式1按钮@%I0.2,模式2按钮@%I0.3,模式3按钮@%I0.4,模式4按钮@%I0.5,正常模式按钮@%I0.6,南北红灯@%Q0.0,南北绿灯@%Q0.1,南北黄灯@%Q0.2,东西红灯@%Q0.3,东西绿灯@%Q0.4,东西黄灯@%Q0.5' --plc PLC_1

# 2) 建 FB 骨架（含 IEC_TIMER 静态量）
& $py 'C:\PLCMCP\ladsim\make_fb_skeleton.py' 'C:\PLCMCP\ladsim\out\fb_tl.xml' 'FB_交通灯' '1' 'C:\PLCMCP\ladsim\if_traffic.json'
& $eng --mode import_lad_xml --xml 'C:\PLCMCP\ladsim\out\fb_tl.xml' --plc PLC_1
& $eng --mode compile_plc --plc PLC_1

# 3) 生成 FB 内部梯形图
& $eng --mode export_block --block 'FB_交通灯' --out 'C:\PLCMCP\ladsim\out\fb_tl_out.xml' --plc PLC_1
& $py 'C:\PLCMCP\ladsim\ladgen_cli.py' 'C:\PLCMCP\ladsim\spec_traffic.json' -o 'C:\PLCMCP\ladsim\out\tl.xml' --base 'C:\PLCMCP\ladsim\out\fb_tl_out.xml'
& $eng --mode import_lad_xml --xml 'C:\PLCMCP\ladsim\out\tl.xml' --plc PLC_1
& $eng --mode compile_plc --plc PLC_1

# 4) 建实例 DB 并生成 OB1 调用
& $eng --mode ensure_idb --db '交通灯DB' --fb 'FB_交通灯' --plc PLC_1
& $py 'C:\PLCMCP\ladsim\make_empty_ob.py' 'C:\PLCMCP\ladsim\out\base_ob.xml'
& $py 'C:\PLCMCP\ladsim\ladgen_cli.py' 'C:\PLCMCP\ladsim\spec_ob1.json' -o 'C:\PLCMCP\ladsim\out\ob1.xml' --base 'C:\PLCMCP\ladsim\out\base_ob.xml'
& $eng --mode import_lad_xml --xml 'C:\PLCMCP\ladsim\out\ob1.xml' --plc PLC_1
& $eng --mode compile_plc --plc PLC_1
```

## 八、在博途里怎么用

1. 打开 `MCP测试项目`
2. 选中 `PLC_1` → 编译（应显示 0 错误）
3. 下载到 PLCSIM
4. 用监控表强制 `启动按钮`(%I0.0) 和 `正常模式按钮`(%I0.6) 为 1
5. 观察 `%Q0.0..%Q0.5` 按 10s/3s/10s/3s 循环变化
6. `倒计时显示`(%MW20) 应逐秒递减

> PLCSIM 的启动、下载、变量强制目前**无法用 MCP 自动完成**（西门子未开放 API），
> 需要手动操作。
